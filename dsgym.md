# DSGym Repository Analysis

DSGym is a unified LLM data science capability evaluation framework, containing three major functions: **evaluation, data synthesis, and trajectory generation**. The core flow is: LLM Agent receives a data science problem → executes code in a Docker sandbox → generates an answer → evaluates with multiple metrics.

---

## 1. `dsgym/agents/` — Agent System

Agents use the **ReAct (Reasoning + Acting)** pattern for multi-turn interaction to solve data science tasks.

| File | Purpose |
|---|---|
| `base_agent.py` | Abstract base class defining `solve_task()`, `reset()` interfaces |
| `react_ds_agent.py` | **Core Agent**: loops — call LLM → execute code → check completion |
| `tci_agent.py` | Standalone agent based on Together Code Interpreter |

### `backends/` — Model Inference Backends

| Backend | Description |
|---|---|
| `litellm_backend.py` | Supports all API providers: OpenAI / Anthropic / Together AI etc. |
| `vllm_backend.py` | Local vLLM GPU inference |
| `sglang_backend.py` | SGLang inference engine |
| `multi_vllm_backend.py` | Auto-spawns multiple vLLM instances by GPU count for max throughput |

### `environment/` — Code Execution Environment

Manages Docker container allocation via `AllocatedCodeEnv` to provide isolated sandboxes for executing Python code generated by agents.

---

## 2. `dsgym/datasets/` — Dataset Loading System

Uses **decorator-based auto-registration** — new datasets only need `@register_dataset("name")`.

| File | Purpose |
|---|---|
| `base.py` | Abstract dataset base class: `load()`, `get_metrics()`, `get_metric_configs()` |
| `registry.py` | Registry: `DatasetRegistry.load("qrdata")` auto-discovers and loads |
| `config.py` | Path management, auto-locates data directories |

### `loaders/` — Supported Dataset Loaders

| Loader | Registry Name | Domain |
|---|---|---|
| `qrdata.py` | `"qrdata"` | Statistical analysis |
| `dabstep.py` | `"dabstep"` | Business analysis |
| `daeval.py` | `"daeval"` | Data analysis |
| `discovery_bench.py` | `"discoverybench"` | Scientific discovery |
| `kaggle.py` | `"kaggle"` | Kaggle competitions |
| `mlebench.py` | `"mlebench"` | ML engineering |
| `bio.py` | `"bio"` | Bioinformatics |
| `econ.py` | `"econ"` | Economics |

### `prompts/` — System Prompt Templates

Instructs agents to analyze problems using the `<reasoning>/<python>/<information>/<answer>` format.

---

## 3. `dsgym/eval/` — Evaluation Framework

| File | Purpose |
|---|---|
| `evaluator.py` | Main orchestrator: `evaluate(agent, samples)` runs full evaluation |
| `metric_registry.py` | Metric registry, auto-selects metrics per dataset |

### `metrics/` — Evaluation Metrics

| Type | Metrics |
|---|---|
| Exact match | `exact_match`, `fuzzy_exact_match`, `list_match` |
| LLM judge | `equivalence_by_llm` (uses GPT-4o to judge equivalence) |
| Semantic similarity | `semantic_similarity` (sentence-transformers) |
| Code execution | `code_execution`, `code_correctness` |
| Domain-specific | `dabstep`, `llm_score`, `hms_score`, `kaggle_submission`, `mlebench_submission` |

---

## 4. `dsgym/synth/` — Synthetic Data Generation (Training Data Source)

### `generators/`

| Generator | Purpose |
|---|---|
| `trajectory_generator.py` | Generates **k trajectories** per sample (pass@k), used to select best training data |
| `query_generator.py` | Agent explores dataset and **auto-generates new query-answer pairs** to expand training data |

### `filters/`

| Filter | Purpose |
|---|---|
| `difficulty_filter.py` | Filters by turn count to control difficulty |
| `quality_filter.py` | Uses **LLM Judge** to score and filter low-quality trajectories/queries |

---

## 5. `examples/` — Ready-to-Use Scripts

```bash
# Evaluation
python examples/evaluate_qrdata.py --model gpt-4o --backend litellm --limit 10
python examples/evaluate_dabstep.py --model gpt-4o --backend litellm --limit 10

# Generate trajectories (synthetic training data)
python examples/generate_trajectories.py --model gpt-4o --dataset qrdata --k 8
```

---

## 6. `src/` — Early Standalone Script Version

Original implementation before `dsgym/` was packaged, looser structure but equivalent functionality:

| File | Purpose |
|---|---|
| `agent.py` | Original Agent implementation (depends on `skyrl_gym`) |
| `generate.py` | Synthetic query generation script |
| `llm_judge.py` | Trajectory quality judge (scores on 6 criteria) |
| `query_filter.py` | Synthetic query quality filtering |
| `select_best_trajectories.py` | Selects best trajectory from k candidates (by judge_score) |
| `src/evaluate/` | Various evaluation entry scripts |

---

## 7. `executors/` — Docker Sandbox Execution Infrastructure

Code generated by agents runs in **isolated Docker containers**:

```
Agent → Manager (FastAPI, port 5000) → Executor Container (Jupyter kernel, port 60000+)
```

| Component | Purpose |
|---|---|
| `generate_compose.py` | Generates Docker Compose configuration |
| `manager/` | FastAPI manager: `/allocate` allocates containers, `/deallocate` releases |
| `container_images/` | Docker images for different workloads (standard DS, bio, Kaggle, GPU) |

---

## 8. `data/` — Data Storage

| Directory | Contents |
|---|---|
| `data/data/` | Raw data files (CSV, JSON) — mounted into Docker containers |
| `data/task/` | Task definition files (each query + ground truth answer) |

---

## Overall Data Flow

```
data/task/   →  datasets/ load    →  agents/ solve
data/data/   →  executors/ run code  →  eval/ evaluate
                                     →  synth/ generate training data
                                          ├── trajectory_generator (generate trajectories)
                                          ├── query_generator (generate new queries)
                                          └── filters/ (filter by quality)
```

## Quick Start

```bash
# Install dependencies
uv sync

# Set API key
export TOGETHER_API_KEY=<your-api-key>

# Run evaluation via CLI
dsgym eval --model together_ai/Qwen/Qwen3-235B-A22B-Instruct-2507-tput --dataset qrdata --limit 10

# Run evaluation via example script
python examples/evaluate_qrdata.py --model gpt-4o --backend litellm --limit 10

# Generate trajectories for training data
dsgym generate --model gpt-4o --dataset qrdata --k 8 --temperature 0.8

# Start Docker execution environment (required for code execution)
cd executors
python generate_compose.py -n 64 --types "executor-prebuilt:64" -m ../data/data
sudo docker build -t executor-prebuilt ./container_images/instance
sudo docker build -t manager-prebuilt ./manager
sudo docker compose -f docker-compose.yml up -d --build
```

## Summary

- `dsgym/` — Packaged framework layer (use this for new work)
- `src/` — Early script layer (legacy, still used in some pipelines)
- `examples/` — Entry points for evaluation and data generation
- `executors/` — Infrastructure (Docker sandboxes for safe code execution)
