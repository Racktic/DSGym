# Dev Log 2026-03-26: Memory V5 — V2 风格 Cross-Task + V4 LLM Summary

## 一、V4 实验结果与问题分析

### V4 实验结果

V4 引入了每轮 LLM summary 生成 task 内 memory + cross-task memory，但结果不如 V2：

| Experiment | Mean % | Above 50% (of scored) | Scored/38 |
|---|---|---|---|
| V4 best | 45.2 | 14/34（41%） | 34 |
| V4 latest | 45.2 | 17/35（49%） | 35 |
| **V2 latest（历史最佳）** | **48.8** | **18/32（56%）** | 32 |
| baseline | 45.9 | 13/29（45%） | 29 |

### V4 退步的根因

对比 V2 和 V4 的 cross_task_memory.json：

V2 的一条 entry：
```json
{
  "plan": "Train an XGBoost regressor with basic preprocessing: handle categoricals via one-hot encoding...",
  "score": 0.303454,
  "insight": "Score: 0.303694 -> 0.303454 (0.1% improvement). Method: XGBoost. Key change: Train an XGBoost regressor..."
}
```

V4 的一条 entry：
```json
{
  "plan": "",
  "score": null,
  "insight": "Standardizing numerical features and using a simple linear model like Ridge Regression can lead to..."
}
```

V4 的 cross-task memory **丢失了具体信息**：plan 为空、score 为 null、insight 过于抽象。

## 二、V5 设计

### 核心思路

保留 V4 的架构（每轮调 LLM 生成 task 内 summary），但 cross-task memory 的写入内容回到 V2 风格：

| 字段 | V2 | V4 | V5 |
|---|---|---|---|
| plan | 模型 goal 文本 | 空 | 模型 goal 文本 |
| score | 正则提取（不准） | None | LLM 提取（准确） |
| model_type | 正则检测 | LLM 提取 | LLM 提取 |
| insight 中的 Score | `prev_best -> new`（固定） | 无 | `ref_score -> new`（跟随 strategy） |
| insight 中的 Key change | `_summarize_plan(plan)` 截断 | LLM 抽象总结 | LLM 比较 reference approach 差异 |

### Summary Prompt 改动

新增 `AIDE_SUMMARY_PROMPT_V5`，相比 V4 prompt：
1. 加了 `=== REFERENCE APPROACH ===` 区块（传入 reference entry 的 notes）
2. `<cross_task_memory>` 里用 `<key_change>` 替代 `<insight>`

### Insight 拼接逻辑

V5 在代码里用 V2 模板拼 insight，但数据来源更准确：
- **improvement**：`"Score: {ref_score} -> {ct_score} ({pct}% change). Method: {LLM_model}. Key change: {LLM_key_change}"`
  - `ref_score`：reference entry 的 score（根据 best_node_strategy 选 latest/best）
  - `ct_score`：当前轮 LLM 提取的准确 score
  - `LLM_key_change`：LLM 比较当前方案和 reference approach 的差异
- **debug_fix**：`"Method: {LLM_model}. Key change: {LLM_key_change}"`
- **第一个 baseline**：`"Baseline score: {ct_score}. Method: {LLM_model}. Key change: {LLM_key_change}"`

### 代码改动（全部增量）

| 文件 | 改动 |
|---|---|
| `aide_prompts.py` | 新增 `AIDE_SUMMARY_PROMPT_V5` |
| `memory.py` | `store_from_summary()` 加 `plan=""`, `score=None` 可选参数 |
| `aide_agent.py` | 新增 `memory_version` 参数；V5 分支用 V5 prompt、传 reference_approach、V2 模板拼 insight、传 plan+score |
| `eval.py` | 新增 `--memory-version v4/v5` 参数 |

| V5 latest | 48.1 | 16/34（47%） | 34 | 89.5% | latest |
| baseline | 45.9 | 13/29（45%） | 29 | 76% | latest |
| V4 best | 45.2 | 14/34（41%） | 34 | 89.5% | best |
| V4 latest | 45.2 | 17/35（49%） | 35 | 92.1% | latest |
| V2 best-node | 45.1 | 13/32（41%） | 32 | 84% | best |
| V3 no-draft | 43.8 | 13/35（37%） | 35 | 92% | latest |
| V2 best+freq | 42.8 | 10/25（40%） | 25 | 66% | best |

### V5 Ablation 实验

| Experiment | Mean % | Above 50% (of scored) | Scored/38 | Submit Rate | 说明 |
|---|---|---|---|---|---|
| V5 best (baseline) | 49.2 | 16/33（48%） | 33 | 87% | V5 完整版 |
| V5 no-task-memory | 48.6 | 16/29（55%） | 29 | 76% | 去掉 task 内 memory 注入 |
| V5 degradation | 48.7 | 13/30（43%） | 30 | 79% | 额外写入失败 improve 经验 |

**Ablation 发现：**
1. **no-task-memory**：mean 只掉了 0.6（49.2→48.6），说明 task 内 memory 增量作用很小——模型通过 conversation history 已有足够历史信息。但提交率从 87% 降到 76%，可能因为没有 task_memory 导致模型对历史尝试的追踪变差
2. **degradation**：mean 掉了 0.5（49.2→48.7），写入失败经验没有帮助，反而略微有害——可能增加了 cross-task memory 噪声，或者"什么不该做"的信息干扰了模型探索

### 关键发现

1. **V5 best (49.2) 是新的历史最高 mean percentile**，超过了 V2 latest (48.8)
2. **V5 latest (48.1) 也明显优于 V4 latest (45.2)**，证明 V5 的 cross-task memory 内容改进有效
3. **V5 best > V5 latest**：best-node strategy 在 V5 下有效（V4/V2 下无效），因为 V5 的 score 追踪准确了
4. **V5 的方差比 V2 大**：mean 更高但 above 50% 比例更低（48% vs 56%），有几个 task 得分特别高拉高均值
5. **V4 → V5 提升 +4.0 (best) / +2.9 (latest)**：仅改了 cross-task memory 内容，证明内容质量（plan + score + 结构化 insight）比抽象 LLM insight 重要
6. **task 内 memory 增量作用有限**：去掉后 mean 只降 0.6，conversation history 已提供大部分信息
7. **失败经验写入无效**：degradation 条目增加噪声，未带来收益

### V5 vs V4 提升归因

V5 和 V4 唯一的区别是 cross-task memory 的写入内容（task 内 memory、注入方式、召回逻辑完全一样）：
- 填回了 plan（V4 是空字符串）和 score（V4 是 None）
- insight 从 LLM 抽象一句话变成 V2 模板（带分数变化 + key_change）
- key_change 由 LLM 和 reference approach 比较生成（比 V2 的 plan 截断更智能）

### best-node strategy 终于有效了

| Version | latest | best | best 提升 |
|---|---|---|---|
| V2 | **48.8** | 45.1 | -3.7 ❌ |
| V4 | 45.2 | 45.2 | 0.0 |
| V5 | 48.1 | **49.2** | +1.1 ✅ |

V2 的 best-node 失败是因为 score 不准（正则提取和模型自报不一致）。V5 的 score 由 LLM 准确提取，best_score 由 LLM 判断 metric 方向，所以 best-node 策略终于能正确找到最优方案了。
