### Ablation on easy test (2×2)

| Config | SmartMem | writeeveryturn | Pub valid | Pub avg %ile |
|---|---|---|---|---|
| baseline | ❌ | ❌ | 2/8 (25%) | 32.6 |
| + memory only | ✅ | ❌ | 3/8 (37.5%) | **60.6** |
| + prompt only | ❌ | ✅ | 2/8 (25%) | 45.0 |
| **+ 组合** | ✅ | ✅ | **6/8 (75%)** ⭐ | 22.0 |

**交互效应**：
- 单 prompt 加不上 valid rate（模型听 "每轮写 submission" 指令，但代码还是崩在 `to_csv` 之前）
- 单 memory 提升 percentile 很多但 valid rate 只微涨
- **两者组合 valid rate 跳到 75%**：memory 让代码更可能跑通 → prompt 的 "每轮写" 才真正生效
- trade-off：combo 多出的 3 个 valid 都是"勉强跑通 + 分数平庸"的 task，所以 avg percentile 从 60.6 降到 22.0

## 4. 核心发现

1. **SmartMem 对 percentile 提升显著**：
   - Easy public 32.6 → **60.6**（+28 pts），接近甚至略超 teacher 均值
   - Hard public 0 → **41.5**（从完全 fail 救到 teacher 水平）
   - 但 valid rate 只微弱提升（2/8 → 3/8，0/10 → 2/10）

2. **SFT 有害 vs memory 友好**：
   - SFT v4 在 easy 上 0/8 valid（比 baseline 2/8 还差），在 hard 上 3/10 valid（比 baseline 0/10 好）
   - 说明 SFT 教会了 hard 类 task 的 pipeline，但把 easy 的格式能力搞坏了
   - 加 cross-task memory 能救回一些

3. **失败瓶颈不在策略，在代码崩溃**：
   - baseline Qwen3-8B 绝大多数 fail 都是代码 runtime error（sklearn API 幻觉、preprocessing drop 掉 target、`n_samples=0` 等），崩在 `to_csv('/submission/submission.csv')` 之前
   - memory 帮助了"写什么代码"（用 CatBoost/XGBoost/LightGBM 替代弱 sklearn），但救不了"代码执行崩溃"
   - 单跑 writeeveryturn prompt：模型 follow prompt（20/20 都写 submission 路径），但还是崩在 to_csv 之前 → valid rate 没变
   - **SmartMem + writeeveryturn 组合才真正 unlock**：memory 先保证代码跑得通，prompt 再保证末尾写 submission → valid rate 从 25% 跳到 75%

4. **ceiling 天花板**：Qwen3-235B teacher 在 easy 上 valid rate 5/8、avg %ile 58.8。**Qwen3-8B + SmartMem 已经 60.6** —— 说明 memory 基本抹平 8B → 235B 的 scale gap（在 valid 的任务内）

5. **final_submission prompt 的 bug**：`AIDE_FINAL_SUBMISSION_INSTRUCTION` 只传 memory_section（文字 summary），**没传 best turn 完整代码**。模型得从 summary 重建 pipeline，常常重现漏掉关键步骤（如 LabelEncoder 在 combined 数据上 fit）导致 final 崩。
