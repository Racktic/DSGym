# MLE-Bench Integration

Date: 2026-04-08

## Summary

Integrated the MLE-Bench "non-lite, non-overlap" set as a new DSGym dspredict
split called `mle_bench`. **Data download was deferred** (see below); the
split is registered, the task JSON is generated, and the loader/CLI can
already enumerate it.

## 1. Task list (47 tasks, not 46)

Recomputed from the canonical MLE-Bench split files:

- `experiments/splits/split75.txt`  -> 74 competitions (full)
- `experiments/splits/low.txt`      -> 22 competitions (lite)
- Full minus Lite                   -> 52 competitions
- Minus 6 overlaps with `hard.json` -> **47** competitions

The previous research note (`dev_logs/mle_bench_research.md`) said 46. The
correct count is **47**: 52 - 6 = 46 was an arithmetic slip; the actual
intersection of `split75 \ low \ {6 overlaps}` is 47 entries. All 47 also
have **zero** overlap with `easy.json`, `hard.json`, and `mle_dojo.json`
(re-verified).

The 6 excluded overlap tasks (already in `hard.json`):
champs-scalar-coupling, stanford-covid-vaccine,
statoil-iceberg-classifier-challenge, tensorflow-speech-recognition-challenge,
tgs-salt-identification-challenge, ventilator-pressure-prediction.

Output:
- `/data/fnie/qixin/DSGym/data/task/dspredict/mle_bench_unique_tasks.txt`
  (47 lines, one task name per line)

## 2. Data download — DEFERRED, NOT EXECUTED

**Status: skipped, awaiting user go-ahead.**

Reasons:
1. The `mlebench` Python package is **not installed** in `.venv` (no
   `mlebench` binary, no module). It would need to be `pip install -e
   examples/MLE_Bench_Eval/mle-bench` first, plus its grader/Kaggle deps.
2. This split is dominated by very large vision / medical imaging /
   segmentation competitions (herbarium-2021/22, hubmap-kidney,
   rsna-breast-cancer, rsna-cervical-spine, vinbigdata, vesuvius,
   uw-madison-gi-tract, siim-covid19, cdiscount, h-and-m, AI4Code,
   inaturalist-2019). Several of these are individually >100 GB. Per the
   user constraint ("if a single task > 100 GB, ask first") this requires
   explicit confirmation.
3. NFS volume `/data` shows 39 TB free out of 275 TB (87% used). Headroom
   exists but downloading 1-3 TB will impact NFS bandwidth for the two
   running training jobs (`distill_gemini_flash_mledojo_remaining` on r-c-03
   and `qwen3_8b_sft` on r-c-30). Should be scheduled around them.
4. Each Kaggle competition requires *manual* TOS acceptance via the
   logged-in Kaggle account before the API will release the data; the
   credential at `~/.kaggle/kaggle.json` exists but accepting 47 sets of
   rules is a one-time human step.

Recommended next session: install `mlebench`, then run a small batch first
(`predict-volcanic-eruptions-ingv-oe`, `us-patent-phrase-to-phrase-matching`,
`tweet-sentiment-extraction`, `petfinder-pawpularity-score`,
`google-quest-challenge` — all <2 GB) to validate the pipeline end-to-end.

Target layout (matches existing dspredict splits, see
`dsgym/datasets/loaders/dspredict.py::SPLIT_CONFIG`):

## 3. Task JSON

Generated by `scripts/build_mle_bench_json.py`. Reads each
`mlebench/competitions/<name>/{description.md,config.yaml}` and emits a
hard.json/mle_dojo.json-style entry.

Output:
- `data/task/dspredict/mle_bench.json` — 47 entries
- avg `description` length ≈ 3430 chars
- 46 of 47 entries have full Description / Evaluation / Dataset Description
  sections parsed from MLE-Bench's `description.md`. The remaining 1
  (`nfl-player-contact-detection`) uses an unusual markdown structure and
  falls back to the file's first paragraph; it is still loadable but the
  description field is shorter (~170 chars) and could be hand-improved later.

Each entry has:
```
challenge_name, description, docker_challenge_path,
competition_description, evaluation_metric, dataset_description,
metadata{domain, keywords[grader], source="mle-bench",
         competition_type, awards_medals}
```

## 4. Split registration

  - Added `"mle-bench": "mle_bench"` to `_split_map`.

## 5. Validation performed

- `dsgym eval --help` lists `dspredict-mle-bench` in the dataset choices.
- The 47-entry JSON is loadable from inside the dsgym Python env via
  `get_task_path('dspredict')/'mle_bench.json'`.
- Did NOT actually run `dsgym eval` (no data on disk yet, and we don't
  want to touch running experiments).

## 6. Known issues / follow-ups

1. **Data not downloaded** — see section 2.
2. **Grader integration** — DSGym currently grades dspredict via Kaggle
   submission API. MLE-Bench tasks need to be graded *locally* against the
   held-out `prepared/private/test.csv` using each task's `grade.py`.
   Either reuse MLE-Bench's per-task `grade.py` directly or write a thin
   adapter under `dsgym/eval/`. Not done yet.
3. **One short description** (`nfl-player-contact-detection`) parses
   incompletely; cosmetic, can be fixed by hand.
4. The new split currently shares no data subdirectory with any existing
   split, so no risk of clobbering existing dspredict data.
